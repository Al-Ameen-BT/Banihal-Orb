4. FINDING 2 — NEXT ROUTE HANDLER /api/chat FAILS CLOSED
--------------------------------------------------------------------------------
  File: client/src/app/api/chat/route.ts

  It fetches ${NEXT_PUBLIC_API_URL}/api/chat = https://172.17.121.200, which
  serves a SELF-SIGNED certificate. Node's fetch rejects it:

      node fetch THREW: fetch failed | DEPTH_ZERO_SELF_SIGNED_CERT

  so the handler always takes its catch branch and answers:

      data: {"error":"The assistant is unavailable. Please try again."}

  Verified live against http://localhost:3000.

  IMPACT: nginx deliberately bypasses this handler (documented in
  /etc/nginx/conf.d/b2b-site.conf - pointing it at :3000 would create an
  infinite proxy loop), so browsers going through 443 are unaffected.
  BUT Next listens on *:3000, so anyone reaching the box directly on port 3000
  gets a permanently dead assistant.

  FIX: firewall port 3000, or point the handler at http://127.0.0.1:3001.

--------------------------------------------------------------------------------
5. RELATED NOTE — AGENT TLS
--------------------------------------------------------------------------------
  The Analytics Agent (https://172.17.122.10:8001) is also self-signed, trusted
  via NODE_EXTRA_CA_CERTS=/opt/B2B-Site/server/certs/agent.pem in server/.env.
  systemd picks this up; any MANUAL run (npx tsx / node) must export it, or every
  signed call fails in ~25ms as 503 AGENT_UNAVAILABLE - which reads as "agent
  down" rather than a TLS problem.
